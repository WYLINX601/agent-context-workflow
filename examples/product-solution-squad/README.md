# 产品方案小队示例

这个示例展示一个组织需求如何进入 Multica 产品方案小队：

```text
用户提出需求
  → 个人助手装配最小 Context
  → 在 Multica 中创建 Issue
  → 产品方案架构师澄清目标并委派角色
  → 用户研究员与竞品／市场分析师并行收集证据
  → 产品方案架构师形成方案总纲
  → 用户评估方案方向
  → PRD 撰写师补齐用户故事与验收标准
  → 红队评审官检查风险与假设
  → 用户评估风险、范围和最终方案
  → 回写产物、决定、事件和能力候选
```

参考配置：[`configs/squads/product-solution-squad.example.yaml`](../../configs/squads/product-solution-squad.example.yaml)。

这是脱敏示例，不包含真实组织、项目、账号、任务或对话数据。

## 角色与边界

本示例从 Multica 中的“产品方案小队”抽取并做了最小脱敏处理，只保留角色职责、工作流和交付约定：

- 产品方案架构师：队长，负责目标、方案总纲、优先级、路线图、交接和汇总；
- 用户研究员：负责用户痛点、场景、人物、旅程、JTBD 和证据置信度；
- 竞品与市场分析师：负责市场、细分、竞品、定位、规模和外部证据；
- PRD 撰写师：负责 PRD、用户故事、功能规格和验收标准；
- 红队评审官：负责前置验尸、风险、假设和最低成本验证建议。

小队不覆盖视觉设计、高保真交互、研发实现、运营和发布执行。Multica 负责 Issue、角色路由、Prompt/Workflow、状态、评论和人工评估节点；本仓库提供公开的结构化参考配置，不替代 Multica 控制面。

## 阶段交付

| 阶段 | 主要参与者 | 阶段结果 | 是否请求用户评估 |
| --- | --- | --- | --- |
| 需求接收 | Lead | 问题、目标、范围、验收标准 | 是 |
| 发现与证据 | 用户研究员、竞品与市场分析师 | 用户洞察、市场／竞品证据、假设与置信度 | 否，必要时升级 |
| 方案总纲 | Lead | 目标、策略、方案架构、模块、优先级、路线图 | 是 |
| 交付细化 | PRD 撰写师 | PRD、用户故事、功能规格、验收标准 | 否 |
| 红队评审 | 红队评审官 | 风险、假设、失败模式、验证建议 | 是 |
| 最终定稿 | Lead + 用户 | 最终方案、开放问题、负责人和下一步 | 是 |
| 写回 | Lead / 工作区 | 产物、决定、事件、知识候选 | 是 |

非 Multica 内的 Agent 如果需要读取 Issue，应通过当前可用的 Multica CLI 获取任务信息；Go ACP Adapter 只负责 ACP 与本地 Hermes Gateway 之间的协议桥接。完整职责边界见 [Multica 控制面边界](../../docs/multica-control-plane.md)。
